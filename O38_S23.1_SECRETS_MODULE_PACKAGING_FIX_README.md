# O38 S23.1 — Stdlib `secrets` Module Packaging Fix

## Problem
The workspace contains `src/core/src/secrets.py`, which shadows Python's standard-library `secrets` module when `src/core/src` is on `PYTHONPATH`. This breaks O36 token issuance because `secrets.token_hex` resolves to the project module.

## Fix
This patch:
1. Renames `src/core/src/secrets.py` to `src/core/src/secret_provider.py`.
2. Rewrites project-relative imports from `.secrets` to `.secret_provider`.
3. Aligns the regression test to import the O36 package as `src.auth`, preserving relative imports.

It does not alter production authentication semantics and does not print or persist credentials.

## Apply
```cmd
python repair_secrets_module_name.py
python -m unittest tests\test_s23_1_secrets_module_packaging.py -v
python -m unittest discover -s tests -p "test_*.py" -v
python -m compileall -q src tests
```
