# O38 S22.1 — Staging Security Mode Fix

This patch fixes a staging security configuration defect discovered during real HTTPS staging validation.

## Root cause
`ProductionSecurityConfig.from_env()` treated `staging` as a non-production mode for the purposes of TLS and authentication, even though O38 staging is intended to be a secure deployment boundary. That allowed S19/S20 to enter the development-only authentication bypass while requests were flowing through real Caddy TLS.

## Fix
For `staging` / `stage`:
- signed-bearer authentication is required;
- TLS termination is required;
- the identity signing secret is required;
- external actions remain disabled;
- automatic memory writes remain disabled.

`development` remains the only local-bypass mode.

## Acceptance
The focused regression adds five deterministic checks covering the staging security contract and preserves the existing development contract.

Real target-environment evidence is still required after this fix; this patch does not declare production readiness by itself.
